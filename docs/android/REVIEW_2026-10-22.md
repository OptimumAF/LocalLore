## Findings and dispositions

1. **Disposal must invalidate a late result.** The initial ViewModel cancelled
   its scope on disposal but did not advance the generation token. A provider
   using same-dispatcher `withContext(NonCancellable)` could potentially return
   after disposal and pass the ticket/revision checks. The coordinator added
   `onCleared()` generation invalidation and a noncancellable-late-completion
   regression. The corrected source was inspected. Test execution/results are
   the coordinator's separately recorded evidence; the reviewer did not claim
   to have run this regression. Real native resource shutdown remains M03.03.
2. **Merged permissions differ from the source manifest.** AndroidX defines and
   requests the app's signature permission
   `org.locallore.app.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION`. An assertion
   requiring an empty requested-permission list would fail despite omitting all
   network/media/contact/location capabilities. The coordinator changed the
   assertion to require exactly this app-owned signature permission and verify
   its protection level. Do not remove AndroidX's protection for a zero count.
3. **Compose includes native helpers.** The built debug APK contains four
   `libandroidx.graphics.path.so` files from resolved
   `androidx.graphics:graphics-path:1.0.1`. Calling the APK Java/Kotlin-only would
   be inaccurate. That dependency's exact official POM/license was added to
   [the source inventory](DEPENDENCY_SOURCES.json). Host alignment checks below
   passed; they do not establish execution on a 16 KB operating system.
4. **Preserve dependency license resources.** The initial Gradle packaging block
   excluded AL2.0/LGPL2.1 resources; the coordinator removed that blanket
   exclusion. The generic Android-default-return-values unit-test setting was
   also removed, keeping pure controller tests from silently stubbing Android
   behavior. The final distribution/NOTICE inventory is still a release gate.

The reviewed finite sample adapter compares raw fake proposals with precomputed
Rust-validated fixture outcomes. It implements no independent Kotlin gameplay
rules and accepts no arbitrary player text or author commands. The UI explicitly
labels fixture/no-real-model/no-native-engine/no-saved-progress scope. Accepted
results alone populate the sample transcript/projection; failures, malformed
proposals and cancellation do not present a successful outcome. Generation
tokens protect reset/cancel races and an older job's `finally` block cannot
clear a newer job's pending state. `onStop` cancels in-flight sample work, while
configuration recreation uses the retained ViewModel for accepted sample state.

These are source-review observations. They do not prove branch switching,
disk/process-death recovery, engine/JNI serialization or cancellation ownership,
real inference, semantic narration safety, or physical-device support. Those
features are outside the finite fixture shell and keep their original gates.
