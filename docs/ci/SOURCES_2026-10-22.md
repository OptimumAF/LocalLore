## Checkout action

Use `actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1`
(`v7.0.1`, upstream latest stable release, published 2026-07-20). The exact
[tag API](https://api.github.com/repos/actions/checkout/git/ref/tags/v7.0.1)
resolved directly to that commit. Review the immutable
[action metadata](https://github.com/actions/checkout/blob/3d3c42e5aac5ba805825da76410c181273ba90b1/action.yml),
[README](https://github.com/actions/checkout/blob/3d3c42e5aac5ba805825da76410c181273ba90b1/README.md)
and [MIT license](https://github.com/actions/checkout/blob/3d3c42e5aac5ba805825da76410c181273ba90b1/LICENSE).
No action source or binary is copied into LocalLore or its Android package.

The action uses the runner-provided Node 24 action runtime; installing Node on
PATH is unnecessary. The upstream minimum runner version is `2.327.1`.
Use the normal event-selected revision, shallow checkout and
`persist-credentials: false`; the upstream default otherwise persists credentials.
The workflow gives `GITHUB_TOKEN` only `contents: read`, as upstream recommends.
No PAT, SSH key or `allow-unsafe-pr-checkout` override is needed. Upstream v7 also
guards unsafe checkout from privileged triggers; LocalLore uses `pull_request`
and a `main` push trigger instead.

## Hosted image and provisioning

The official [runner-image index](https://github.com/actions/runner-images/blob/c87f6f636fffa43205bc05328efe9958af0f984f/README.md)
maps `windows-2025` to the VS2026 image. Its
[software inventory](https://github.com/actions/runner-images/blob/c87f6f636fffa43205bc05328efe9958af0f984f/images/windows/Windows2025-VS2026-Readme.md)
reports image `20261007.264.1`, Python `3.12.10`, Rustup `1.29.1`, Java
`17.0.20+101` via `JAVA_HOME_17_X64`, Android command-line tools `19.0`,
SDK platform 36, Build-tools `35.0.0` and NDK `29.0.14206865`.
Use the versioned OS label rather than `windows-latest`. This does not freeze
the VM image: upstream updates hosted images weekly. Inspect actual run setup
logs before reporting hosted versions or success.

LocalLore selects its existing Rust `1.93.1` toolchain with rustfmt/clippy and
the two Android targets. It selects Java 17 through the image's named environment
variable, the checked-in Gradle wrapper and the project's existing exact SDK/NDK
versions. The image's default Rust, Gradle and NDK can differ and are not the
project's selected versions. The reviewed Android/Rust dependency and licensing
decisions remain in [Android toolchain notes](../android/TOOLCHAIN_2026-10-22.md)
and [native sources](../native/SOURCES_2026-10-22.md).

Google's [sdkmanager documentation](https://developer.android.com/tools/sdkmanager)
specifies individually quoted package paths, exact NDK package versions and
separate interactive license acceptance. GitHub's
[image build source](https://github.com/actions/runner-images/blob/c87f6f636fffa43205bc05328efe9958af0f984f/images/windows/scripts/build/Install-AndroidSDK.ps1)
preinstalls standard license records in the hosted image. LocalLore must not
copy those records, synthesize acceptance or pipe an affirmative answer into
sdkmanager. Provisioning may rely on already accepted licenses in the supplied
environment; missing acceptance must fail for owner review. No local check
command provisions SDK packages or accepts licenses.

## Workflow trust boundary

GitHub's [secure-use guidance](https://docs.github.com/en/actions/reference/security/secure-use)
supports full commit pins, minimum token permissions and avoiding privileged
untrusted-code execution. The workflow contains no secret references, caches,
artifact uploads, environment deployments, reusable remote workflows or
self-hosted/larger runners. PR title/body/branch text is not interpolated into
shell scripts. Checks execute contributor code on disposable standard hosted
runners. This is still untrusted code execution with network access; read-only
permissions and local static review do not prove arbitrary contributor code safe.
Repository settings and fork approval policy remain owner-controlled and are
not changed by this packet.
