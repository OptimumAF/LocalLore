# D05 shared Host query integration

Refs #26 D05.01–.07 partial shared prerequisite, claim6357293223; shared #10/#11.
This is stacked on D04/shared base46f3ef3. No D05 acceptance, native rendering,
frontend UI, advanced memory or inference result is inferred from this packet.

`inspection_query { session, query }` is generated from Rust into the host-v1
JSON Schema and frontend request types. The strict Query carries scope, expected
current head, optional inspected completed-turn head, observer, view, search,
limit and cursor. The Host's trusted constructor supplies the Story Lab grant;
renderer JSON cannot set it. Session scope and liveness are checked first.
Durable Host capture reloads one validated SQLite Engine snapshot before the
module checks the expected head. Derivation/replay then runs on that immutable
clone outside the Host lock, without a provider call or storage write. A later
commit does not rewrite that page; a new page needs its current expected head.

The module is now public under `cfg(feature = "host")`; its15 tests import the
actual public module rather than temporarily including its source. Unsupported
summaries/retrieval indexes and unsupported branch history remain explicit.
The query never supplies content or a grant to generation. Existing legacy
Inspect/PlaySnapshot and Android contracts remain additive and compatible.

The first focused suites passed15 module tests and2 actual Host/SQLite tests;
strict Clippy passed. The wire tests deny private/omniscient lenses on an
unprivileged Host, reject an injected `story_lab_granted` field, enforce session
scope, reload an externally committed head, rebuild revision0 while reporting
current head1, separate Mira's mistaken belief from the player's hidden secret,
and keep play snapshots, story time and live workers unchanged while browsing.
The test initially expected an invented InvalidEnvelope category; the actual
strict-envelope error is Malformed, and that assertion was corrected.

Independent source review subsequently found two observer leaks before release:
witnessed effects were incorrectly used to grant an NPC the player's raw input
and narrator transcript, and a global promise-completion flag disclosed a private
ledger inference to the creditor. NPC history now contains witnessed events only;
spoken text stays available in the original witnessed Said event. Raw player
messages and narrator display text require the Player or Omniscient lens. Promise
completion contributes neither status nor a source entry until that observer can
see its evidence. Status is labeled a derived comparison, including clock-based
open/overdue interpretation; a hidden completion cannot create a Withheld entry
that itself reveals the transition.

The expanded module suite passes16 cases, including unchanged NPC promise rows,
provenance and search/count before/after an unwitnessed completion; TurnDiff
does not invent a creditor-visible fulfillment. Player still sees canonical
fulfilled. The v2 historical-input regression also proves NPC event visibility
does not disclose raw input or narrator messages. Actual Host/SQLite2 tests and
strict all-target Clippy pass after these fixes. These are source/module/native
Host tests, not native WebView or frontend-render evidence.

Schema generation uses the actual Rust example. Type generation uses the exact
existing `build.mjs` compile options and already installed pinned dependency,
without duplicating node_modules. Only generated schema/types are checked in;
local caches/evidence stay ignored. Final command rerun and closed-session
coverage are recorded in the integration commit/ticket handoff.

Still required: frontend query controller/cache keyed by complete context,
deliberate Story Lab spoiler acknowledgement, native rendered inspection/history/
pagination/provenance/keyboard journeys, current integration compatibility and
the shared memory prerequisites for the full D05 exit gate. This source packet
does not make private inspection a hostile-renderer security sandbox.
