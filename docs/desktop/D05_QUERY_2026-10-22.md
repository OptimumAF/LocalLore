# Bounded shared inspection query prerequisite

Refs #26 D05.01–.07 (partial); shared #10/#11/#8 retain memory, retrieval and
persistence ownership. This packet is a read-only Rust query module plus synthetic
tests, based on `1ab04bc` (accepted D03 plus explicitly prototype M05 integration).
It changes no existing engine rule, context compiler, Host/schema, storage,
migration, Android or desktop source. Native UI/IPC integration and full D05
acceptance remain coordinator work. No task checkbox or owner acceptance is claimed.

## Frozen API

```rust
pub fn query(
    engine: &Engine,
    request: &Query,
    story_lab_granted: bool,
) -> Result<Page, QueryError>;
```

The caller supplies an immutable, validated Engine clone from the authoritative
head. `story_lab_granted` is trusted native configuration, never a request property.
The coordinator must add the feature-gated module declaration and wire Host/schema
separately; this packet does not expose another native or JSON command.

`Query` is strict serde input with optional host-feature JsonSchema derivation:

| Field | Meaning |
|---|---|
| version | Exactly QUERY_VERSION=1 |
| scope | Exact current story/root branch; no cross-story lookup |
| expected_head | Must equal the supplied Engine's current head, including for historical reads |
| at_revision | None=current; Some(0)=seed; otherwise a completed receipt boundary |
| observer | Player, Character{id}, or Omniscient; other characters and Omniscient require trusted Lab grant |
| view | Profiles, History, Relationships, Knowledge, Promises, Provenance, TurnDiff, Summaries, RetrievalIndexes |
| cursor | Optional bounded structural continuation for this exact query/snapshot |
| limit | 1–64 rows |
| search | At most 256 UTF-8 bytes; literal case-insensitive substring of eligible serialized rows, including IDs and provenance; controls rejected |

`Page` echoes scope, current head, inspected revision/story time, observer, view,
privacy and status. `total` counts **matching eligible rows**, not actors or turns.
Rows have typed Field/Clock/Event/Message/Relationship/Knowledge/Promise/Provenance/
Change variants and stable unambiguous JSON-tuple keys. Response rows are
Serialize-only; returning an accepted Effect does not introduce a deserialization
route to canonical history. Errors are fixed enums without source paths or raw
private exception text.

## Eligibility and provenance

Player/character queries first obtain that actor's existing `character_context`.
Only its observation IDs authorize event/claim/message sources; only its permitted
facts and beliefs enter knowledge results. Scoped profile fields come from that
actor's own context, with only owned inventory. Lab's all-actor profile view still
obtains each actor's own context separately. It never produces a combined NPC
generation context. Every query is a derivation; no inspection lens advances time,
calls inference, commits a turn or writes character knowledge.

Relationships preserve the accepted D03 rule: scoped lenses inspect their own
outgoing edges only; Lab Omniscient may inspect every direction. Respect, trust and
obligation remain distinct, with independent source links. Promises preserve D03
eligibility: own outgoing promises, or incoming promises whose creation event is
actually observed. Incoming seed commitments are not assumed known merely because
the recipient ID matches. Status uses existing Commitment::status at the inspected
story time: open, overdue or fulfilled. No new deadline or knowledge-transfer rule
is introduced.

Field provenance consults existing progression_sources. Source tags distinguish
Seed(id), Event(sequence) and Withheld. The last is used when context permits a
current value but the latest supporting event is not observed; it must not be
presented as seed-origin or an exposed hidden event. Knowledge rows distinguish
canonical truth, recorded statements, subjective beliefs with confidence,
recorded discoveries and observed history. A false statement never becomes a
truth row. Truth retains seed provenance; discovering it adds its observed
acquisition event. Beliefs retain source-claim and change-event links.

Filtering happens **before search, row identity assignment, count, cursor binding
and pagination**. In particular, belief ordinals are assigned after filtering;
adding an unseen NPC belief must not shift the player's row IDs or cursor.
Neither an omniscient count nor hidden canonical bytes enter cursor checksums.

History returns only eligible accepted events, with sequence, turn, story time,
participants, witnesses and typed consequence. Original dialogue/free-text input
and recorded narration are attached only when every event supporting that receipt
is visible; full raw requests/proposals/model profiles are not attached. Rows sort
chronologically by sequence, with original input before its first event and
narration after the last event. An uncommitted preview is absent.

## Historical state and bounds

Historical queries use Engine::replay on the actual completed receipt prefix.
TurnDiff compares observer-filtered state/knowledge/relationships/promises and clock
before and after the selected complete turn. It does not relabel today's projection
with an old timestamp. V2 replay retains original free text and recorded approved
outcomes without an inference provider. Partial-turn/future revisions reject;
changed current heads reject with Stale even if the historical selection remains.

The current durable contract owns root branches only. A mismatched query scope
rejects with Scope; an actual in-memory fork Engine rejects with UnsupportedBranch.
This does not invent branch names or pretend durable sibling timelines exist.
Summaries and RetrievalIndexes return explicit Unsupported status, no rows/count
and a missing-feature explanation. They never fabricate a summary or freshness
status. Aliases, motivations/background and additional relationship dimensions
are also explicitly unimplemented. NarrativeV1 profiles omit numeric RPG fields
that its rules do not implement.

Cursors are at most 128 bytes, include a canonical offset and SHA256 checksum
bound to the entire query, eligible matching rows and offset. Changing scope,
observer, view, revision, search, limit, visible content or offset invalidates a
copied cursor. They are **not authentication or integrity attestations**: a caller
can compute a new checksum, but every call still performs current grant and
eligibility checks before paging. No cursor grants access to another lens.

Serialized pages cap at 64 KiB, and pagination may stop before the requested row
limit to preserve that budget. A single oversized visible row fails closed with
TooLarge; it is not silently dropped. Candidate derivation is capped at 65,536
rows. This first implementation scans/replays the supplied bounded history; it is
not a streaming database index, semantic retrieval system or measured long-history
performance result. Large source-state allocation/replay costs remain a future
profiling concern. These are source API bounds, not OS memory guarantees.

## Actual verification and handoff

All code changes are confined to new `crates/locallore/src/inspection_query.rs`,
new `crates/locallore/tests/inspection_query.rs` and this document. The standalone
integration test temporarily path-includes the module with public core re-exports
until the coordinator adds the library declaration. Existing optional host SHA256
and schema dependencies suffice; no new dependency or manifest edit is required.

Actually run on Windows x64 / Rust1.93.1 with own `target/d05-query`, dev/test debug=0,
incremental=0 and cached dependencies:

```powershell
rustfmt +1.93.1 --edition 2021 crates/locallore/src/inspection_query.rs crates/locallore/tests/inspection_query.rs
cargo +1.93.1 test -p locallore --features host --test inspection_query --locked --offline
cargo +1.93.1 clippy -p locallore --features host --test inspection_query --locked --offline -- -D warnings
git diff --check
```

Final focused result: **15 passed, zero failed/ignored**, 0.03s; strict Clippy and
format/diff checks passed. Tests exercise private canaries across search/count/
single-row pagination/provenance, hidden-belief cursor stability, Lab denials and
separate NPC lenses, edited/cross-query/stale cursors, completed-turn replay/diff,
future discovery exclusion, v2 original input replay, statement/belief/truth
distinctions, directed attitudes, witnessed versus seed promises, deadline status,
row and byte pagination, oversized-row refusal, versions/scopes/branch/unsupported
views, narrative genre fields and immutable-clone reads during independent commit.
The v2 test initially omitted two existing PlayProfile hash fields and failed to
compile; the fixture was corrected before the final passing suite. No production
failure was hidden or weakened to obtain the result.
