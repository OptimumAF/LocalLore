## Commands and authority

These additive host-v1 commands use the existing native `Host::call` path:

```json
{"version":1,"command":{"op":"trace_configure","session":"session-1","scope":{"story":"synthetic","branch":"main"},"expected_head":1,"enabled":true}}
{"version":1,"command":{"op":"trace_read","session":"session-1","scope":{"story":"synthetic","branch":"main"},"expected_head":1,"base_revision":0,"observer":{"kind":"player"},"turn":"gift","attempt":1}}
{"version":1,"command":{"op":"trace_clear","session":"session-1","scope":{"story":"synthetic","branch":"main"},"expected_head":1}}
```

`turn` and `attempt` may be omitted/null. The wire attempt is a u64 constrained by
Host to the collector's u32 range. The observer is D05's existing tagged observer.
The strings above are illustrative synthetic handles, not a runnable saved story.
Each command first validates an open session, exact story/branch and current
Engine head; durable Hosts reload the authoritative SQLite owner before comparing
`expected_head`. `base_revision` selects the captured turn basis, not the current
head. A stale command cannot change configuration or delete metadata.

Capture defaults disabled. Configure applies to this entire window's Host and is
explicitly labeled `configuration_scope: "window_host"`. Disabling or clearing
deletes private in-memory trace data and invalidates old handles. Nothing is
written to a save, file, database or exported bundle. The normal player can read
only the actual player observer. A different character or omniscient inspection
requires the native constructor's Story Lab grant, never renderer JSON. Character
selection remains exact: selecting Mira returns no player attempts even in Lab.
An omniscient Lab read may inspect the original player attempt with its original
identity; it does not relabel the trace or grant generation knowledge.

Each open session owns an opaque, non-serializable `TraceOwner`. Read filters this
identity before cloning metadata. Closing and reopening the same saved story or
replacing an owner cannot reveal the old session's attempts. Global retention
exposes no other observer's drop/eviction count. A trace itself is neither a
capability nor evidence that an effect committed.

A read's `data` contains the actual scope, current `head`, `base_revision`, supplied
observer, `configuration_scope`, `capture: "metadata_only"`,
`full_capture: "unsupported"`, and the detached `snapshot`. Its disabled form is:

```json
{"version":1,"status":"disabled","exact_reconstruction":false,"attempts":[]}
```

An enabled snapshot says `status: "bounded_metadata_window"`. Attempts retain
scope, base revision, actual observer, turn and local attempt number, provenance,
terminal/running outcome, monotonic elapsed microseconds, truncation and typed
stages. No raw prompt, context, output, story prose, excluded record IDs, exception
text or local path is captured. Known runtime/profile hashes and revision come
from the exact trusted `LocalPlay` configuration copied into the worker lease;
`config_sha256` hashes that serialized configuration. Prompt version uses the
actual `play::PROMPT_VERSION` constant. Full rendered prompt/schema hashes and
engine source revision remain null rather than borrowing a misleading identity.
Synthetic typed mode says `deterministic-fake-v1`.

The collector retains at most 32 attempts, 24 stages per attempt and 63,488 bytes
including its snapshot envelope. Host reserves another 2,048 bytes for reply
metadata and verifies the complete serialized reply is at most 65,536 bytes.
Dropped/evicted/disabled/poisoned traces are not reconstructed from receipts.
A busy or poisoned read reports `TraceUnavailable`; explicit reconfigure/clear
can discard poisoned diagnostics and recover. Gameplay hooks use only try_lock
and ignore unavailable, stale, invalid or truncated handles.

## Production lifecycle

The ordinary production prepare path creates one attempt handle and gives it to
`RingSink` around the existing `play::execute_traced`, operating on the already
existing cloned Engine. It does not copy context selection, create another
provider path or change the persisted Receipt. The configured provider factory
and inference run outside Host, persistence and trace locks. Existing production
hooks report real intent, context, director, parsing, repair, validation,
accepted-candidate and narration intervals; unsupported retrieval/memory remain
honest not-run markers. Legacy typed synthetic inference gets only its observed
accepted-candidate interval, not invented role spans.

`publication` measures actual Host reconciliation of the worker lease with
current session, cancellation, head and durable status. Provider panic is caught
by the pre-existing worker boundary; publication can report the observed fixed
`provider` category without pretending a completed director span was captured.
The final attempt is still running after ready; the actual ephemeral
`Engine::commit_prepared` or SQLite `Persistence::commit_prepared` is timed as
`atomic_commit`. The existing canonical engine/store decides every result.

Lost commit acknowledgement follows the existing lookup: a saved matching
receipt proves this candidate committed; an independently winning receipt makes
this candidate stale. If acknowledgement and lookup both fail, atomic_commit is
`unknown`, the attempt stays running and Host preserves `TransportUnknown` and
its retryable lease. Later real saved status can finish the attempt without
fabricating a generation/commit interval. A cached retry, including restart with
no loaded model, calls no provider and fabricates no trace. Close/cancel/stale
publication finish only what was observed. A failed close cancellation records
unknown; it does not advertise a durable cancellation. Reopened failed receipts
retain null failure cause when that cause was not persisted.
