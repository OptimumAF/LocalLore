## API and ownership

```rust
let mut ring = TraceRing::default(); // disabled, retaining nothing
ring.set_enabled(true);             // metadata capture only
let begun = ring.begin(identity, provenance);
if let Some(handle) = begun.handle {
    // After the actual production stage; statuses are diagnostic only.
    let _ = ring.record(&handle, Stage::Validation, Outcome::Rejected,
                        Counts::default(), Some(ErrorCategory::Ability));
    let _ = ring.finish(&handle, Outcome::Rejected);
}
// Trusted caller identity is independent of the requested selection.
let snapshot = ring.read(&selection, &Reader::scoped(scope, observer));
ring.clear();                       // local in-memory deletion, invalidates handles
ring.set_enabled(false);            // also clears retained data
```

`AttemptIdentity` contains exact scope, **base_revision**, observer, turn and
attempt number. Base revision is the captured turn basis, not a current Engine
head assertion. IDs are nonempty bounded ASCII engine-style IDs. The collector
cannot validate canonical freshness; the integrating Host must independently
check session scope/current expected head before returning private metadata.

`Begin` returns a diagnostic `HookStatus` and optional opaque `AttemptHandle`.
Handles bind an internal collector owner and monotonically assigned attempt
sequence, are process-local, and are not serializable or engine authority.
Foreign, evicted, cleared and finished handles cannot append or reopen a record.
Duplicate retained attempt identities drop rather than overwrite. This is a
single-owner mutable collector; a Host adapter may hold a short best-effort lock.
Lock poisoning/contention or inability to record must never propagate into the
gameplay Result. The collector itself has no lock, Engine reference, callback,
provider, filesystem, network, persistence or arbitrary execution capability.

`Stage` covers Intent, Retrieval, Context, Director, Parsing, Validation, Repair,
AcceptedCandidate, Narration, NarrationValidation, AtomicCommit and
MemoryMaintenance. `Outcome` distinguishes NotRun, Running, Accepted, Rejected,
Committed, Failed, Cancelled, Stale and Truncated. They record what trusted hooks
observed; the collector does not validate a pipeline or decide a commit succeeded.
The coordinator must only emit a successful stage after that real stage succeeds,
and explicitly mark known not-run stages rather than invent them from missing data.

Timing uses `Instant`, with nonnegative microseconds since attempt start and
durations between successive hook marks. The first interval starts at begin.
These are hook-boundary intervals, including intervening caller/observer overhead;
they are not independent model-compute or tokenizer measurements. A finished
attempt stores elapsed time. An abandoned handle remains Running at its last
recorded mark; dropping it does not guess Failed or Cancelled. Its snapshot is
explicitly incomplete, never an exact reconstruction.

`Provenance` has optional model/worker/profile/config/prompt/schema SHA256 hashes,
runtime/engine Git revisions and profile/prompt/schema version labels. Constructors
validate 64/40 hex widths and lower-case hashes; labels permit at most64 ASCII
alphanumeric/period/underscore/hyphen characters. Missing identities serialize as
null. Labels must identify trusted software/profile versions, never input text or
excluded source identifiers; validation of character syntax is not semantic
redaction. No raw model path, prompt/config body or error string can enter a stage.

`Counts` accepts only eligible-record counts, operation/repair counts and optional
input/output token counts carrying Measured versus Estimated. Integrators must
derive these from the actual already-filtered context, never excluded records.
There is no exclusion-ID/count field, source-record identifier list, model output,
context body, wall clock, device identifier or free-form exception field.

## Authorization and bounded retention

`Selection` chooses scope, base_revision, observer and optional turn/attempt.
`Reader` is a separate trusted type without Deserialize: scoped readers require
exact scope and observer; native Story Lab readers may select another observer
within that exact scope. Changing the selector observer cannot relabel a retained
player attempt into an NPC attempt. Privileged construction must remain outside
renderer/model input. This is an application authorization boundary, not an OS
or hostile-process sandbox. Trace data never enters character generation context.

`Config` permits 1–32 retained attempts, 1–24 stages per attempt and a serialized
snapshot budget of 1024–65,536 bytes. Default maxima are32/24/64KiB. Whole Snapshot
JSON, including version/status/exactness metadata and punctuation, is measured
after each mutation; oldest attempts are evicted until the complete response
fits. A single oversized attempt may be dropped. A filtered read is no larger
than the measured full window. These bounds cover serialized API data and finite
collections, not allocator/OS failure guarantees. Snapshot values are detached
clones for subsequent immutable preview by an integrating application.

Stage overflow retains the bounded prefix, marks truncated and never silently
records a later successful finish over the truncated outcome. Byte/attempt
eviction yields Dropped for old handles; the query intentionally exposes no
global eviction/drop counters that could describe other observers' activity.
Every enabled snapshot says BoundedMetadataWindow and exact_reconstruction=false,
even when its visible attempts happen to fit. Empty enabled data does not assert
that no gameplay occurred. Disabled capture is explicit and empty. No missing
stage is reconstructed from current state or recorded receipts.

`request_full_capture()` always returns Unsupported. There is no raw capture,
retention file, export route, background worker or opt-in UI in this packet.
Future full capture requires the actual explicit local consent/retention/delete/
preview integration and its tests; metadata enablement grants none of those.

## Compatibility with accepted M03.06

Read current #7 and its accepted merge/criterion reconciliation, ADR-0005 and
Android `Diagnostics.kt` before implementation. This prerequisite follows their
fixed categories, bounded process memory, detached snapshot, explicit deletion
and absence of raw exceptions or automatic export/upload. `ErrorCategory::from_engine`
matches the existing typed core errors directly, preserving Ability/Knowledge/
Inventory/etc. Timeout is named Deadline here; missing errors use Option::None
and unknown external categories must map to Unknown, never their string.

This is a scoped shared stage format, not a replacement Android diagnostic export
format. Existing M03.06 JSON v1/export preview behavior and its limits are unchanged.
No format conversion, Android UI wiring or device execution is claimed. Future
adapters must explicitly map categories/outcomes; they must not embed Android log
snapshots or add a second logger/export subsystem.
