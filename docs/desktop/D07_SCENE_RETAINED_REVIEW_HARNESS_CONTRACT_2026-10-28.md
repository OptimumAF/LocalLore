## Closed purpose and preserved defaults

Add exactly one launcher argument, `--native-scene-review-v1`. The existing
`--native-scene-v1` remains the one actual paired batch1/resume3 cohort; native3
and no-argument scripted defaults retain their existing scenarios and oracles.
The new mode reads an already completed genuine Native4 run through the same
catalog, native controller, managed reader, public inspection and IPC paths.
It does not reconstruct a report, canonical engine state or controller state.

Review performs no comparison start, generation, import, ordinary model load,
weight copy/link, new publication root, download, fake provider or fallback.
Its `modelExecution` is false even when a retained report records actual old
native profile/load/roles. Report provenance describes that original execution,
not a newly loaded model. Supporting sequence/consent counters do not
independently authenticate SDK physical loads.

## Required narrow Root-only native plumbing

Current source inspection demonstrates that the existing stage/profile plumbing
is insufficient: `LOCALLORE_TEST_RESTART` currently maps only1 to `restart`, and
all dev WebView profiles are derived from the workspace parent. Passing the old
workspace without a profile change would write its old profile. Passing a fresh
workspace would lose the existing comparison root. Neither is acceptable.

Proposed smallest Root seam uses existing stage plumbing, without a new
bootstrap field, command, permission or renderer selector:

1. Recognize the closed value `LOCALLORE_TEST_RESTART=review` only under checked
   active Scene4/full/native/D02 flags. Emit existing trusted `stage:'review'`;
   optional `config.scene` remains the current native-derived expectation.
   Normal/legacy/ordinary cohort initial/restart behavior stays unchanged.
2. Under that same exact native review gate, derive the new profile exclusively
   from the existing validated fresh `LOCALLORE_D02_ARTIFACT_DIR` parent, rather
   than the retained workspace parent. Validate ordinary D: output ancestry,
   distinct fresh UUID root and disjointness from the retained workspace.
   No arbitrary new profile-path argument or general app setting is introduced.
3. Expose fixed source markers/helper names agreed with Root so the launcher can
   refuse unsupported source before building/launching review. Root must verify
   final source/product binding. Running a missing review-stage seam could
   otherwise select the old initial journey; missing isolation must fail closed.

Suggested native helper names are `review_active()` and
`review_webview_profile(...)`, compiled only with dev-harness. Root owns the
exact implementation and focused refusal tests. The Node/TS author does not
edit Rust/main/bootstrap. No broader persistence, inference or model ownership
capability is requested. Existing import/load guards remain authoritative.

## Completed resume preserves current Rust source gates

Current Rust checks `index.matches_current()` before its completed-resume
read-only fast path. A retained genuine report can open/read historically while
resume returns `EvaluationSourceMismatch` after source changes. Review must not
move, bypass or weaken that gate, rewrite an index/fingerprint, run an older
binary as the new UI, or regenerate a report to manufacture resume success.

After observing an actually completed open, one explicit existing `resume(1)`
may return either its genuine completed result or this exact authoritative
source-mismatch refusal. Record the actual branch, service error and bounded
frontend/native error evidence honestly. A historical refusal is not a successful
completed resume; its accepted open/read/render evidence remains separate. No
other start/resume or repair follows it. In both branches require identical
retained file inventories and unchanged zero sequence/consent/no-owner
observations, with no unexpected errors. Other failures stop rather than become
an unavailable-success label. The existing fresh-source cohort oracles are not
changed by this separate historical-review behavior.
