## Process, storage and failure policy

Current selected launcher is not the process-policy baseline: its unbounded
`execFile` Git precedes admission; `run` settles on exit, misses pipe errors,
does not distinguish PID errors, kills without bounded drain and only rejects
overflow afterward. It inherits harness aliases, has no permanent storage latch,
physical-D admission or normal-build finally restore. Preserve these facts and
historical evidence; do not claim the old helper already meets D06 policy.

Reuse the accepted D06 `live-git-policy-v1`/`live-child-policy-v1` behavior and
`unchangedSource`, `unchangedProducts`, `footprint`, `measureStorage`, final restore
patterns from `live-narration-harness.mjs`. They are not an importable helper
library: importing that launcher would execute work. Apply the bounded behavior
directly in the selected launcher with unique test extraction markers, no general
runner framework. Keep frozen D06 tests/source unchanged. A safety strengthening
shared by legacy modes must be explicit and retain their journey/roster oracles;
never silently weaken old tests to accommodate the new mode.

All Git, including initial source admission and final restoration checks, uses
the same permanent owner barrier. Cap each stdout/stderr at256KiB, Git15s and
128 Git records; await direct `close`, distinguish spawn/noPID from errorWithPID,
handle both pipe errors, and preserve PID/signal/kill/timeout/overflow evidence.
Timeout attempts one kill and at most5s direct-child drain. Timeout, output
overflow, PID/pipe error or unknown close permanently blocks every later child,
Git and restoration, even after late close; do not claim process-tree containment.
A verified known-close nonzero/noPID spawn failure fails that admission without
inventing an unknown child. Normal restoration can follow only fresh successful
source/storage checks and no unknown/storage latch, never another app run.

Before every child, require committed clean source revision and frozen input
hashes; before app launch require immutable built frontend/executable hashes.
Use serial fixed frontend build, offline locked dev native build, initial app,
restart app, then normal frontend/native restore; no automatic workload retries.
Native builds select `--bin locallore-desktop-spike`, jobs1 and existing target.
Keep Cargo900s, frontend240s, app960s (existing app watchdog900s) bounds. Never run
the offline qualifier, launcher-supplied arbitrary command or normal application.

Proposed target/source ceilings retain D06 values: target growth2GiB and
source/frontend output growth128MiB; contract and each new authored source
contribution stay below1MiB. Root's budget precision distinguishes expected later
harness evidence at most64MiB, hard per-packet256MiB and cumulative qualification
evidence512MiB. The1MiB freeze counts in these evidence totals. Record actual
already consumed evidence and remaining admission before a later run; a new
packet does not reset the cumulative cap. Baseline actual target/source/free D
before packet creation. Full inventories use safe checked sums/entry bound;
failure or overflow permanently latches storage and blocks all further launches,
including restoration. Aggregate caps apply even when individual PNG/fixture
limits would allow more bytes. No cap reset, automatic fresh packet, deletion,
model copying/download, cache relocation or repair to regain budget. Root admits
one cumulative execution budget later; this proposal creates no runtime root.

On failure retain original failure/checkpoint/error/process and partial fixture
bytes. Finally restore normal frontend and normal no-default-feature desktop
build only after known closure/source checks/storage admission, record whether
attempted/passed/skipped, and never launch it. Report final complete measured
packet/target/source bytes after closure, or unavailable/last-known when unsafe.
The model directory stays absent; ordinary app status/shutdown may inspect that
absent task-owned candidate. No independent SDK-load counter or universal zero
model-file-probe claim is made. No model status/reservation test owner is added.
