## Implemented source and authority

The [consumer contract](D08_DOMAIN2_FORK_CONTRACT_2026-10-30.md) freezes interfaces,
limits and missing evidence. Core already provides the complete canonical list,
including author-only intervals. The new fixed `fork_boundaries` native adapter
reuses the existing coherent Host snapshot read, returns only version/scope/head/
boundaries and discards coverage/Engine details. Unsupported Domain2 derived
coverage does not disable neutral metadata or grant memory/generation capability.
The reply is capped at4097 entries and64KiB in both encodings; input is exact,
bounded and scope/head/session bound. Existing WindowLease checks fence admission,
cancellation and publication. No Core/Host/Store/schema/dependency/provider changed.

The UI reads that whole list and exposes coherent Domain2 Play/Story Lab fork
selection. It does not synthesize boundaries from receipts or0/head. Catalog
preparation is context/catalog bound; confirmation is current-request/current-
consent bound. Rendered callbacks are tied to current gameplay and the exact Fork
snapshot, including same-context request/result replacement. Main synchronizes
starting/pending/disposed/V2-pending/uncertain admission, including synchronous
notification ordering. A block during the pending notification revokes consent
before dispatch; later blocking leaves an already dispatched operation recoverable.

Existing fork_start/fork_lookup/archive status/cancellation, stable recovery-v1
identity saved before dispatch, immutable retry and explicit child opening remain
the mutation/lifetime owners. Metadata refresh has its own sequence and does not
retire the fork operation or transfer consent. Fork/read/open/recovery makes no
provider call or automatic downstream replay. The next fresh turn uses existing
player admission. Rewinding before author history may correctly reopen Domain1;
after-author history remains Domain2. Inspector privileges do not change knowledge
or generation input permissions.
