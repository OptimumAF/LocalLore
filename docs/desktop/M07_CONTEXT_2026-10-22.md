## API and eligibility

```rust
pub fn compile(engine: &Engine, request: &CompileRequest)
    -> Result<ContextPackage, CompileError>;
```

The request includes exact scope/current expected_head/optional inspected completed
revision, selected actor, Director or Character role, bounded lexical query,
explicit known-ID references and Budget. Director requires the actual player;
Character selects exactly one existing actor. There is no Omniscient, Story Lab,
inspection-grant, summary or external-index input. Caller authorization and trusted
actor selection remain the integrating Host's responsibility.

Scope/current-head/root-history/completed-boundary/actor validation precedes any
compiler source serialization or relevance work. Historical state is rebuilt once
with existing Engine::replay and then uses that exact inspected snapshot. Future
and partial-turn boundaries reject. Actual forks reject UnsupportedBranch; they
are not silently treated as roots or relabeled current sheets.

The prototype reuses Engine::character_context observations and current public
inspection_query Profiles/Knowledge/Promises/Relationships. The latter's internal
trusted boolean is encapsulated in a helper that constructs ONLY
Character(selected_actor). No caller may select another lens or inject a grant.
This reuses the fixed D05 eligibility/status/provenance rules rather than creating
another witness/knowledge predicate. Event content is projected only after the
existing Engine actor filter; raw requests, player display prose and other
observers' full contexts are never retrieved. Prototype compilation/tests currently
require `--features host`; root will promote the shared eligibility port and
resolve module/dependency gating during production integration.

Eligible truth, recorded statements, subjective beliefs, discovery, observation,
canonical state, directed relationship and commitment rows retain their existing
typed origin and source tags. Source event IDs are eligible IDs; source_revision
is the latest visible supporting event (seed=0). Package revision separately
states the inspected projection boundary. Withheld source IDs stay withheld.
The compiler never decides truth, changes a projection or creates a memory ledger.

## Selection and budgets

Mandatory records are:

- rules/profile/version and fixed authority/intent/knowledge policies;
- exact existing actor state/inventory/abilities/current location;
- all known truth and current subjective beliefs, separately labeled;
- own eligible directed relationships and unresolved open/overdue commitments;
- configured recent accepted events and visible source evidence for pinned rows;
- latest eligible event supporting an explicit known reference, plus resolved
  identity labels for referenced known actors.

The rules block identifies current Engine/profile authority and constraints; it
does not invent a full numeric ability catalog. The production action guard and
Engine remain authoritative for costs/prerequisites/routes. The prototype does
not yet replace production nearby-scene/route assembly or expose the full future
M06 identity/alias/rules catalog. Integration must preserve those established
interfaces rather than pretending this packet replaces all scene compilation.

Explicit case-sensitive IDs resolve first against eligible IDs only. Current
canonical display names are a limited alias source: only actor IDs already present
in eligible state/observations/relationships/commitments may be looked up. A global
actor-name scan is forbidden. A hidden actor with the same name does not create a
false ambiguity; ambiguous names among known actors stop with AmbiguousAlias
unless the caller supplied an exact matching known ID. An explicit hidden versus
nonexistent ID produces the same UnknownReference category without echoing it in
diagnostics. There is no alias registry, fuzzy matching or invented identity.

Remaining eligible rows rank deterministically by exact-ID overlap*10,000 plus
literal lexical token overlap*10, then descending source revision, then stable ID.
Fixed event tags recognize Give/gift/transfer, promise/commitment, speech and
discovery without changing those events' meaning. Query has at most512 UTF-8 bytes
and64 distinct words; explicit IDs cap at16. Lexical scoring scans the complete
bounded eligible record, including a keyword at the tail of a long statement.
SQL/FTS-looking input is just words; no SQL parser or database call exists here.

Bounds:8192 eligible rows,2MiB serialized eligible candidates,256 known actor
identity labels of at most256 bytes each,128 selected records,32 detailed omission
entries. Excess source bounds fail closed. Output cap is1024–24,576 bytes;
estimated total context cap is at most4096 tokens with explicit reserved tokens
subtracted. Recent accepted events cap at8, optional selected rows at64.

The **whole** ContextPackage JSON, including accounting/diagnostic/unsupported
fields and punctuation, is measured to a stable fixed point. Token accounting is
explicitly `estimate_utf8_bytes_div_4_not_measured`, ceiling(bytes/4). This is not
a tokenizer measurement or proof of model/template/output fit; actual tokenizer
validation and model-specific margin remain required before production generation.
If mandatory rows do not fit, compilation returns MandatoryBudget. Optional
records may be omitted; diagnostic detail is trimmed before mandatory data.

Diagnostics contain only eligible candidate counts and selected/omitted eligible
IDs/reasons. They contain no excluded IDs/counts/name matches or raw query echo.
Omission detail truncation is explicit. Rule/alias records are compiler metadata,
so the table's selected total includes them while eligible_candidates counts the
actual source rows. Diagnostics should remain in trusted debug views; production
may render only selected records into its prompt after accounting for that exact
rendered form. Full context/debug capture still requires its owning consent policy.
