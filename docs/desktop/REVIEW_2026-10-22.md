## Framework recommendation and checked upstream versions

Prefer Tauri 2 for this bounded Windows spike: a direct Rust call removes a
second desktop JNI adapter and keeps the existing engine authoritative. HTML
forms and tables are a practical starting point for later Story Lab search and
inspection. This is an engineering judgment from the source boundaries, not a
measured performance/accessibility advantage. React/TypeScript can follow in
D02; a static JS spike still needs schema validation from the versioned source
of truth, not independent handwritten wire types.

The smallest comparison is an equivalent engine call and lifecycle analysis;
building a parallel Compose product is unnecessary. Rollback cost stays small
if portable host-v1 contains no Tauri types and all web/native code remains in
`apps/desktop`. A later Compose UI could call that same service through a new
transport. Android remains Kotlin/Compose/JNI.

## Security-sensitive implementation checks

**App command ACL is explicit.** Tauri documents that app commands registered
through `invoke_handler` are available to all app windows/webviews by default.
An empty plugin capability does not restrict these app commands. Declare the
command through `tauri_build::AppManifest::commands`, enable only its generated
allow permission for the intended window, and independently bind the native
window/principal to allowed host operations. Never trust a JSON field to grant
an author/debug role. See [capabilities](https://v2.tauri.app/security/capabilities/).

**Configure CSP and block remote navigation.** CSP protection requires explicit
configuration. Ship local scripts/styles, render story text as text rather than
HTML, allow only required local IPC connections, and avoid remote assets,
iframes, general filesystem/shell/HTTP/SQL plugins and external-page IPC grants.
Keep the initial window local and block unintended navigation/new windows.
See [CSP](https://v2.tauri.app/security/csp/) and
[Tauri process model](https://v2.tauri.app/concept/process-model/).

**Scope is authorization, not presentation.** Before state/context/receipt
serialization, validate session ownership, story, branch, observer and requested
revision. A play observer must never receive raw `Projection`, hidden seed or
unfiltered canonical receipts simply because the frontend can hide fields.
A developer inspector requires an explicit host-granted capability. D01 can
report that capability unsupported. A snapshot must label the same revision
across all of its fields.

**Transport uncertainty is normal.** The authoritative host owns a single
serialization point for each session. Work runs on bounded workers over clones
outside that critical section. Close/reset invalidates an operation even when
its worker retains temporary memory. Commit rechecks cancellation, operation
identity and revision, and preserves exact retry semantics. Before canonical
mutation, ensure the complete prospective success reply fits the output cap;
otherwise a committed turn may appear as a transport failure.

## Required adversarial cases for implementation review

These are concrete review inputs/expected outcomes, not a second ticket tracker.
The coordinator should map them to named host tests and native evidence.

| Case | Expected observable result |
|---|---|
| Malformed/invalid UTF-8 JSON, unknown field/op, wrong host/domain version, negative/fractional/overflow integer, cap+1 bytes | Bounded error without private input echo; no engine change or worker allocation. Check exact cap edge and multibyte input. |
| JS ID/revision greater than 2^53−1 | Reject before precision loss or encode opaque IDs as strings; Rust u64 acceptance alone is insufficient for JS. |
| Foreign session/story/branch/observer or unsupported author capability | Rejected before context creation; no actor/hidden-state leakage through snapshot, event or receipt lookup. |
| Exact duplicate request after accepted revision advances | Same stored canonical receipt, no repeated provider work/reward; changed payload with same scoped turn ID yields retry mismatch. |
| Commit response dropped then lookup/retry | Turn status/receipt resolves accepted outcome; frontend never assumes rollback or applies a new turn to stale state. |
| Two clients begin at revision N, then one commits | Second mutation fails stale or is explicitly busy; never replaces newer state from a draft. |
| Cancel pending/running/prepared; race cancel against commit | Cancellation before commit preserves canonical bytes. Commit winner is reported accepted/already committed. Never claim rollback of an accepted receipt. |
| Close during work, double close, new session, late worker completion | Old handle becomes unusable; close semantics documented; late completion cannot alter/reopen the new session. |
| Snapshot while another turn commits | Every snapshot is coherent and revision-labelled; requested historical revision is served coherently or explicitly rejected. |
| Failed/malformed/rejected/oversized provider output | No canonical change; terminal operation status remains queryable and worker capacity is released. |
| Session/turn/worker cap reached; cancellation and cleanup | Bounded resource error, no unbounded spawning; capacity recovered according to documented retention semantics. |
| Prepared success output at cap+1 | Reject before commit; no accepted history hidden behind `TooLarge`. |
| Untrusted text containing markup/script/URL | Display as inert text, no external request/navigation; unknown window cannot invoke privileged app command. |
| Same fixture through headless and real native command | Canonical receipt/state equality; evidence must distinguish Rust adapter tests from an actual WebView IPC invocation. |

Persistence, export, arbitrary seeds, author edits, real models, real free-text
interpretation and graph rendering remain unsupported/deferred. A deterministic
fixture should be described as synthetic plumbing wherever it appears. Native
launch/IPC evidence and Android compile/JVM checks belong to coordinator
verification; the baseline test run above does not substitute for them.
