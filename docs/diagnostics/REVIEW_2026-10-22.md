## Concrete findings and changes

1. **Stale picker result could bind to newer consent.** A cancelled/dismissed
   review originally removed all pending state. Android delivers a URI without
   an app-level snapshot ticket; reopening/exporting before the old result
   returned could attach that old destination to a new snapshot. Coordinator
   added a separate outstanding-picker latch: revocation removes consent but
   does not permit another launch until the previous callback drains. Read the
   updated implementation and requested a regression with dismiss/reopen/late
   callback/new export ordering.
2. **Cancellation listener could run provider code on main.** An initial
   `invokeOnCancellation { signal.cancel() }` could synchronously invoke a
   provider-installed listener on the thread cancelling the job. Coordinator
   moved this into a lazy IO cancellation task, bounded alongside the single
   writer with a global semaphore. The permit remains owned while either body
   or listener is still active. Requested a slow synchronous listener test and
   second-open exclusion until release.
3. **Cancellation is not file rollback.** `CreateDocument` providers can keep an
   empty/partial document, ignore cancellation or already have completed the
   copy. Requested explicit UI wording and fixed notices that do not promise
   deletion/rollback. A user-selected provider can store plaintext JSON in the
   cloud; this is stated before export. No external provider was contacted by
   this reviewer.

These are implementation review findings, not authorization to relax privacy
or introduce telemetry. The first two fixes were read in coordinator source.
Final integration/device results belong in the coordinator's verification
artifact; source review alone does not prove execution.

## Follow-up integration review and independent controller checks

Freshly read the completed coordinator integration and its controller,
ViewModel-diagnostic, native/Compose integration and document-writer tests.
The updated dialog explains plaintext JSON, cloud-backed providers and partial
copies after cancellation/failure before the user chooses export. No additional
blocking production defect was found in this reviewed source.

In the writer, provider open and stream lifetime stay inside IO. Every normal
write, cancellation-after-open and write failure closes the stream before that
worker exits. The separate cancellation task is joined if active, otherwise
cancelled, in `NonCancellable` cleanup before the semaphore permit is released.
A provider that ignores cancellation can delay this cleanup indefinitely, but
cannot accumulate more provider opens/cancellation listeners through repeated
exports. Waiting exports remain coroutine-cancellable. This bounds app-created
provider work; it does not bound or repair arbitrary provider code.

Read the actual regression for a synchronous local cancellation listener: it
checks main-dispatcher responsiveness, first-descriptor closure, exclusion of a
second open while cleanup is held, then permits completion after explicit test
release. Other writer tests cover exact bytes, truncation, byte limits, invalid
schemes, null/error providers, failed writes and repeated closure. These were
reviewed as tests; this reviewer did not execute them on Android. A test-only
remote provider's runtime/classloader problem is an instrumentation-harness
failure, not evidence that any production writer check passed; coordinator
verification must record its repair and actual rerun.
