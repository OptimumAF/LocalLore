## Android document export

- [Storage Access Framework guide](https://developer.android.com/training/data-storage/shared/documents-files):
  document creation uses the system picker and user-selected provider; this
  access needs no storage permission. A provider can be cloud-backed, and the
  exported document survives app uninstall. Explain this boundary before export.
  A picker cancellation need not return a URI. The app must never infer consent
  from a restored URI alone or automatically send an export to an issue tracker.
- [CreateDocument API](https://developer.android.com/reference/androidx/activity/result/contract/ActivityResultContracts.CreateDocument):
  use the MIME-specific `CreateDocument("application/json")` constructor and
  a fixed, nonpersonal suggested filename. The pinned 1.10.1 source creates
  `ACTION_CREATE_DOCUMENT` with MIME type/title and returns data only for a
  successful activity result. A null result is a normal cancellation path.
- [ContentResolver API](https://developer.android.com/reference/android/content/ContentResolver#openFileDescriptor(android.net.Uri,%20java.lang.String,%20android.os.CancellationSignal)):
  the cancellable three-argument `openFileDescriptor` overload is available from
  API 19, below minimum 26. Its general API also accepts file URIs; this app should
  explicitly restrict export destinations to `content` URIs obtained from the
  picker. Request `wt` to truncate: plain `w` does not reliably truncate across
  providers. A provider crash can yield null. The caller owns the descriptor.
- [AutoCloseOutputStream API](https://developer.android.com/reference/android/os/ParcelFileDescriptor.AutoCloseOutputStream):
  available since API 1. Keep stream/descriptor ownership within one worker-side
  scope and close on every path, including failure after opening. No descriptor
  should cross a cancellable coroutine return boundary without cleanup.

The official APIs support cancellation signalling, not an atomic document
transaction. A provider can ignore cancellation or retain an empty/partial file.
Cancellation after a completed write cannot retract that copy. The UI/report
must describe this limitation; no deletion or rollback guarantee follows.
Use no persistent URI permission and retain no destination URI in saved state,
diagnostics or logs. A plain JSON export is readable by its chosen provider.

## Coroutines and ownership

The live [suspendCancellableCoroutine API documentation](https://kotlinlang.org/api/kotlinx.coroutines/kotlinx-coroutines-core/kotlinx.coroutines/suspend-cancellable-coroutine.html)
currently describes 1.11.0. This packet does not upgrade from 1.10.2. Reviewed
the [exact 1.10.2 continuation source](https://github.com/Kotlin/kotlinx.coroutines/blob/1.10.2/kotlinx-coroutines-core/common/src/CancellableContinuation.kt)
and its [Apache-2.0 license](https://github.com/Kotlin/kotlinx.coroutines/blob/1.10.2/LICENSE.txt).
Cancellation handlers may run concurrently. Register the platform cancellation
signal before opening a provider; use an IO worker, check cancellation before
opening and before writing, and release the stream even if completion delivery
is cancelled. Prompt cancellation does not forcibly interrupt arbitrary provider
code. `resume(Unit)` after closing avoids returning an owned resource that could
be lost at dispatch. A handler should not perform blocking close work on the UI
thread. Bounds apply to app-owned records/snapshots, not arbitrary provider code.

## Required implementation regressions

Review/export must use one immutable bounded snapshot; the bytes written must
equal its visible preview even if new diagnostic entries arrive. Dismiss, clear,
stale picker callback, duplicate callback, process death and ViewModel disposal
must not authorize a later write. Configuration recreation may retain the same
reviewed in-memory snapshot. Tests should reject non-content URIs, null/crashed
providers, private exception strings, failed/partial writes and cancellation
before/while opening. Verify worker-only provider calls and closure of every
opened descriptor. These are review requirements, not a claim tests have passed.
