## Current official Android document semantics

The [Storage Access Framework guide](https://developer.android.com/training/data-storage/shared/documents-files) states that ACTION_CREATE_DOCUMENT creates a new document and disambiguates an existing name instead of overwriting it. A selected provider can be cloud-backed: show plaintext/full-private disclosure before export and retain explicit consent; this is not a promise that exported files stay device-local.

[ContentResolver.openFileDescriptor](https://developer.android.com/reference/android/content/ContentResolver#openFileDescriptor(android.net.Uri,java.lang.String,android.os.CancellationSignal)) documents that rw implies a seekable on-disk descriptor, while exclusive r/w may use pipes; actual mode behavior varies by provider and w may truncate. A null descriptor can mean a crashed provider. [ParcelFileDescriptor.getStatSize](https://developer.android.com/reference/android/os/ParcelFileDescriptor#getStatSize()) returns -1 for non-files. Therefore use a SAF content URI, rw with no truncation, and verify that same opened descriptor is empty and seekable before any write. Refuse nonempty/unknown/nonseekable targets rather than falling back to w/wt/delete/recreate. Descriptor/stream closure remains required on every path; a partial newly created document may remain and must be disclosed. Provider/OS blocking and externally concurrent or malicious provider mutation have no universal hard-preemption/atomic-publication guarantee.

Import limits apply to actual bytes read, with a one-byte overflow probe after the 32MiB allowance; names, MIME, provider-reported size and available() do not prove content length. No persisted URI grant or broad storage permission is needed. Readiness, cancellation, stale picker return and disposal must be exercised at the actual controller boundary; no source-only design is labelled a device pass.
