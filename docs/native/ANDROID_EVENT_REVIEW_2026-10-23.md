## Required authority boundary

An event reference is a typed ID copied from Source::Event or Message.event_ids in the current eligible player page, not an integer parsed from human text, title, key or source labels. Seed and Withheld sources cannot become links; labels resembling Event #N must not grant a read. No arbitrary event-ID read is added. The query remains fixed current story/branch/head/Player over the existing inspection_query; Rust visibility applies before literal search/count/pagination. No observer grant, SQL, canonical write, inference, Host/schema/storage change or new dependency is involved.

Current accepted Rust History serialization emits EventRow sequence as a bare numeric property before scope, and serializes user/narrator text as escaped strings. A fixed `"sequence":N,` literal excludes sequence 10 when requesting 1 and cannot match embedded quoted text whose quotes are escaped. This is a bounded dependence on the accepted serialization, not a new query operator or authorization token. The adapter must still require exactly the requested event row and metadata; literal substring matching alone is insufficient.

Successful detail needs the same fixed query/context/head/clock and a single recorded-observation Event whose typed sequence equals the authorised reference, nonempty turn and scoped event metadata. Zero/multiple/mismatched rows, wrong section/privacy/origin/head, malformed/future sources and failed reads must not yield a replacement event. Back must restore the original frozen page/search/section/cursor without issuing a new page read. New detail/page queries, Back, dismiss, story/head changes, gameplay/recovery and disposal must revoke late publication, including a reader that ignores coroutine cancellation.
