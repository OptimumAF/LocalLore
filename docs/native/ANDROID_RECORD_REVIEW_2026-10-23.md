## Integration and decoder findings

Current integration adds a gateway reader without gameplay commands. It captures session/scope/head, rejects pending operations, sends only fixed Player/current-head inspection_query, rechecks its captured owner after the await, and then decodes. ShellViewModel gates opening on persistent selected/idle/non-recovery state, dismisses reads before gameplay/recovery/story changes, and disposes the controller before closing the gateway. MainActivity's existing onStop calls cancel, which now dismisses the record even when no gameplay turn is busy. Dismissed/disposed retained record callbacks see no context and cannot open another native query.

Source review identified malformed-frame gaps in the provisional decoder: missing nullable fields passed JSONObject.isNull, future event/source IDs and empty/duplicate message evidence IDs passed, foreign-owned inventory could be represented as a player profile item, and event story time could exceed page time. The coordinator added corresponding presence/scope/numeric/evidence checks before execution. [Android JSONObject documentation](https://developer.android.com/reference/org/json/JSONObject#isNull(java.lang.String)) explicitly treats a missing mapping as null, so presence must be checked separately. Additional exact variant/required-field/range checks and the resulting tests remain under review.

The actual current Rust Engine::revision returns the last accepted event sequence, not receipt/turn count. Therefore current Page.head bounds event/source sequence IDs even when one accepted turn has multiple events. This was rechecked against Engine::revision and Page construction rather than inferred from the one-event demo. No future revision basis is silently assumed.

A whole-file edit introduced mojibake separators during decoder corrections; the reviewer reported it before freezing and recommended escaped Unicode separators. This is a presentation-source finding, not a reproduced device failure. No actual JNI schema mismatch or secrecy violation is claimed from provisional source alone.

The native-test draft correctly treats SECRET-TIDE as a fact known to the player in this seed, and separately searches hidden NPC beliefs/background canaries. Three native cases and one collected UI flow compare actual accepted player snapshots/receipts before/after browsing, retain distinct statement/belief/truth origins, exercise native observer-grant rejection, paging and strict reopen, then dispose and prove resource ownership. These assertions are source-reviewed, not yet execution evidence.

Review caught an ASCII-only cursor check: a syntactically arbitrary canary token would pass despite the test expecting rejection. Current Rust emits `1:<positive offset>:<64 lowercase hex>` with offset below the matched total; validating that structure/range does not claim authentication or reproduce engine query-binding hashes. Requested malformed nullable/evidence/owner/cursor regressions accompany the decoder corrections. Test-source review also requested missing UI imports, the public JUnit failure aggregator, and NonCancellable final cleanup so cancellation cannot bypass bounded model/transport drain and root cleanup.

The controller JVM fixtures deliberately retain the dispatcher while using NonCancellable. [Kotlin withContext documentation](https://kotlinlang.org/api/kotlinx.coroutines/kotlinx-coroutines-core/kotlinx.coroutines/with-context.html) distinguishes this from a dispatcher-changing return that discards results on cancellation. Thus the planned same-dispatcher late-success/late-failure fixtures can test the controller generation fence. They are not actual native execution/cancellation or hardware/model evidence.
