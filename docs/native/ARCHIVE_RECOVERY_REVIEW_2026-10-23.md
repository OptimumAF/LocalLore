## Interruption boundaries

The proposed Android experiment externally force-stops the verified isolated application while a real Activity/native preview or acknowledged import is held. It must prove actual target process absence, launcher/client cleanup and subsequent fresh process restart. This is different from Activity recreation, low-memory process reclamation, power loss and interruption inside Android's SQLite import transaction. Intentional held-arm termination is an interruption record, never a passing test. Host-owned subprocess kills independently exercise real Store transaction atomicity and postcommit/preack uncertainty; those are Windows host checks, not Android midtransaction evidence.

Existing Store import cancellation polls place the first callback before transaction work, the second immediately after inserting the story, and the third after the first branch insertion. Blocking a test-owned callback at the latter boundaries can expose a genuine uncommitted writer transaction to an independent reader/writer before killing only that owned child. It must show old reader state and competing writer Busy, then reopen/replay to old state with retained control-story equality. A separate accepted-commit/preack hold must reopen as one complete import, with exact bytes/three-branch receipts/canaries and same-ID Conflict rather than treating uncertain import retry as idempotent success. No production hook or altered Store rule is needed.
