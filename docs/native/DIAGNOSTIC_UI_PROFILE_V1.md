## Cancellation, byte binding and cleanup

New activation `_bound` and controller `_raw` hash the exact bytes consumed as
well as retaining path checks before/after. Equal-length bytes temporarily read
from a different version must not be decoded or returned. The existing shared
JSON helper already checks its consumed bytes and remains unchanged.

Dispatch/qualification exceptions keep the overall run failed even if a
controller finished just before cancellation and cleanup/closed storage can be
verified. The remaining safe cleanup tails are still attempted. Known closure
and overall success are separate facts; an exception cannot be healed by later
positive metadata. Failure reasons expose categories, not private exception text.
One spent stop request is never retried. Unknown observer, owner wait, capture,
publication or source state refuses qualification and cannot release a live
reservation as if closure were known.

The SDK capture closes each socket/sender/input inside its individual operation;
its final `close()` is a poison-only API returning `None`. The controller rejects
unexpected final returns or exceptions. Process capture and live observer close
have separate strict `True` completion contracts. These meanings are not coerced.

The existing ceilings stay90seconds/method,1200controller,1230caller,1700owner,
1730parent,1800outer,400readiness. The outer supervised interval begins after
preflight; it is not a whole-CLI hard deadline. No retries or deadline extensions
are added. Source reads have their existing file/byte bounds. Host verification
uses independent180-second process owners; the full suite may be split into
source-identical cohorts so every required assertion runs without enlarging that
ceiling.
