## SDK cache feasibility, independently inspected

The exact SDK remains LiteRT-LM 0.18.1, revision `bda624851d74be34d4e1f7fac1fc4155939539c7`. Its [provider implementation](https://github.com/google-ai-edge/LiteRT-LM/blob/bda624851d74be34d4e1f7fac1fc4155939539c7/runtime/components/constrained_decoding/llg_constraint_provider.cc) creates an LLGuidance tokenizer per provider and frees it on destruction. Its callback retains a pointer to the SDK tokenizer. The [provider header](https://github.com/google-ai-edge/LiteRT-LM/blob/bda624851d74be34d4e1f7fac1fc4155939539c7/runtime/components/constrained_decoding/llg_constraint_provider.h) also owns backing vocabulary vectors. Sharing the raw pointer while preserving those destructors is unsafe.

The [public Kotlin configuration](https://github.com/google-ai-edge/LiteRT-LM/blob/bda624851d74be34d4e1f7fac1fc4155939539c7/kotlin/java/com/google/ai/edge/litertlm/Config.kt) exposes no tokenizer-sharing parameter. Conversation reuse would also retain interaction state; disabling response formatting or making the required schema nullable would change the product contract. The pinned [clone implementation](https://github.com/google-ai-edge/LiteRT-LM/blob/bda624851d74be34d4e1f7fac1fc4155939539c7/runtime/conversation/conversation.cc#L835-L864) calls the provider factory again and copies session/history state, so it supplies neither this cache nor fresh-role isolation. Moving expensive conversation creation ahead of the unchanged deadline is not a tokenizer-cache implementation.

A narrowly scoped native design would need an engine/config-owned tokenizer bundle, with explicit vocabulary/EOS/special-token identity, backing-buffer and callback-owner lifetime, synchronized construction and safe teardown. Each conversation must retain independent mutable constraints, history and KV state. Thread safety of the shared tokenizer callback must be established, not assumed from a `const` provider method. The existing [provider tests](https://github.com/google-ai-edge/LiteRT-LM/blob/bda624851d74be34d4e1f7fac1fc4155939539c7/runtime/components/constrained_decoding/llg_constraint_provider_test.cc) use a tiny mocked vocabulary: cache identity, single construction, failure/retry, cancellation, concurrent use and final release can first be tested without a model.

Local read-only metadata establishes JBR 17.0.6, NDK 29.0.14206865, CMake 3.22.1, Ninja, Rust and Visual Studio installations. The Gradle 0.18.1 module cache contains the prebuilt AAR and POM, not a native SDK source archive. No Bazel/Bazelisk executable, standard Bazel repository cache or SDK checkout was found in the targeted locations inspected. This is a bounded search, not proof of machine-wide absence.

Consequently an offline native SDK rebuild from currently verified caches is **not established**. The pinned [build guide](https://github.com/google-ai-edge/LiteRT-LM/blob/bda624851d74be34d4e1f7fac1fc4155939539c7/docs/getting-started/build-and-run.md) requires Bazel 7.6.1.
