Native JNI methods use the **existing NativeWorkspace handle** only:

- `register(handle, bytes, consent)` parses exact `{version:1,session,input}`; `input` has precisely `parent`, `child_branch`, `expected_parent_revision`, `at_revision`, matching desktop47ab8d7. It stores immutable input and actual `Arc<Lease>` identity before worker dispatch and returns opaque operation/status. It does not create a child or claim a validated completed-boundary preview.
- `run(handle, operation)` borrows the existing registry mutation/control/Host owner and calls only accepted `Host::fork_branch`. Kotlin IO is the worker; JNI creates no threads/Java reference/Store/path. A second worker is Busy, terminal run returns its retained result, same pending registration returns the same operation, different pending input is Busy. A new explicit terminal retry gets a new native operation but retains the same canonical four-field child identity.
- `status` / `cancel` operate only on the same handle+operation. Cancel of registered work makes a terminal Cancelled before any worker executes; running cancellation is cooperative. A committed Host return wins late cancellation. Cancelled does not prove a child absent from an earlier committed retry.
- `lookup(handle,input)` calls only existing Host branches catalog. It compares fixed child+original parent+fork, rejects retired/mismatched identity and returns current child head. Missing is an honest catalog snapshot and **never calls fork**, including after process restart. No session, inspection/observer or author capability is minted by metadata lookup.

Bounds: one retained registered/running/terminal operation per actual owner; at most4 owner slots; global nonreused positive operation IDs through i64MAX; input/output4096 bytes; session1–128 UTF-8 bytes; IDs1–64 ASCII alphanumeric/underscore/hyphen; expected head0–9007199254740991 and fork0–expected, matching the desktop caller. This caller bound does not change Store's original creation-only expected-head semantics. Existing-child retry still returns its current head despite later parent advancement. No input/model/prose/SQL/path field is accepted.

Close marks the existing lease closed before taking the short operation-map lock, then removes/cancels that operation **before** existing mutation/control/Host drain. This orders concurrent registration: it sees closed or is subsequently retired, so no late pending registration can retain a closed Host and exhaust the4-owner budget. Operations never hold registry/phase locks during Host work. Same existing locks serialize accepted deletion and session invalidation before a fork can run. Canonical branch retirement still belongs to the existing shared deletion/retention ports.

## Kotlin controller and exact recovery

`NativeForkGateway(workspaceHandle: suspend ()->Long)` opens nothing. Root supplies the existing NativeWorkspaceTransport allocator. Registration acknowledges in noncancellable IO, binds owner/operation/input and cancels an early/closed/context-epoch acknowledgement before returning it. Native run uses IO; brief cancel is independent of that worker. Gateway close cancels its operation but never closes another owner's workspace; NativeWorkspaceTransport remains the sole handle lifecycle owner.

`BranchForkController(scope,gateway,saveRecovery,onResolved)` captures native session/scope/head/view/observer/epoch and a fixed UUID (or explicitly supplied child ID) on prepare. Confirmation requires the **same rendered immutable input object**, explicit consent and matching context. The injected synchronous `saveRecovery` must durably save the exact version1 four-field input or throw **before native registration**; save failure dispatches nothing. No pending operation ID/session is restored as authority.

Normal uncertainty retains the exact input and permits only an explicit same-incarnation retry. `restore` and changed context make recovery lookup-only. Lookup absence does not recreate a child. Forgetting an identity requires its own explicit consent and successful recovery-store clear; it neither deletes nor promises absence of a child. New child IDs are generated only by explicit prepare, never error recovery. Polling is bounded200 status reads/25ms intervals, then honest uncertainty.

Cancel within the same live dialog does not discard a subsequently observed committed result. Close/session/head/lens/epoch switch clears presentation, cancels late acknowledgements, drains the old coroutine before new prepare and suppresses stale results; no old source labels a new selection. Confirmed outcome refresh failure cannot hide the accepted outcome. Neither adapter nor controller resumes/selects the child automatically or alters knowledge/grants.

New wire decoding bounds UTF-8 bytes, exact fields, primitive integer/boolean types, versions, parent/child/fork/current-head identity and fixed error categories. The new finite ASCII-ID/fixed-label/integer control format additionally requires a canonical JSONObject round trip (ignoring only JSON whitespace outside strings), refusing duplicate keys, lenient syntax/trailing objects and overflow/version truncation. It is not a general story JSON parser or a new history authority; actual Android JSONObject/JNI execution is separately pending.
