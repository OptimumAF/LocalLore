## Source findings and required observations

**No-restart is a different runner topology, not proof by itself.** Android15 no-restart attaches to an existing target and skips ordinary startup/finish force-stops. Runtime evidence must still establish the live target, saved task and actual callback after death; runner termination alone is insufficient. [Android15 ActivityManagerService](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/android-15.0.0_r1/services/core/java/com/android/server/am/ActivityManagerService.java).

**Saved-state flags need a lifecycle and identity context.** The exact server dump fields are `mHaveState`, `mIcicle`, `state`, `finishing` and conditional `mAppStopped`. `mHaveState` starts true for an unlaunched record, so it alone proves nothing about a completed save. Require the exact private fixture record/task, STOPPED, non-finishing, stopped-app state, and a non-null saved bundle before admitting the kill handshake. A stopped callback without a bundle can result from timeout. The source updates non-null saved state before completing STOPPED. [Android15 ActivityRecord](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/android-15.0.0_r1/services/core/java/com/android/server/wm/ActivityRecord.java).

The reviewer initially recommended package-filtered activity dumping as server-only. Actual settlement output contradicted that claim. Rechecking Android15 AMS showed that `-p` itself enables client dumping; omitting `-c` is insufficient. That recommendation was incorrect. The corrected server-only text command is plain `dumpsys activity activities`, with a bounded output cap and exact host-side component/task selection. Future admission must explicitly cover its broader server metadata and reject client-detail sections. [Android15 dump dispatch](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/android-15.0.0_r1/services/core/java/com/android/server/am/ActivityManagerService.java), [ATMS forwarding](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/android-15.0.0_r1/services/core/java/com/android/server/wm/ActivityTaskManagerService.java).

Pre-death STOPPED and post-death task retention need different profiles. The process-death cleanup sets a retained record to DESTROYED and detaches its process. A post-death check should require that same saved, non-finishing record/task with APP absence, rather than mistakenly requiring it to remain STOPPED.

The source-supported foreground query is `dumpsys window displays`. Parse one display-zero focus/app pair and corroborate it with the fresh XML package. The APP's Activity class lies outside its application-ID prefix, so its short component still contains the full class name. Null, exiting, conflicting or other-display-only focus cannot authorize a tap. [Android15 display dump](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/android-15.0.0_r1/services/core/java/com/android/server/wm/DisplayContent.java), [server command dispatch](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/android-15.0.0_r1/services/core/java/com/android/server/wm/WindowManagerService.java).

**The pinned runner has an independent Activity finisher.** Official Google Maven monitor 1.7.2 source confirms `MonitoringInstrumentation.finish` normally schedules an Activity finisher; `waitForActivitiesToComplete=false` disables that path. Its first `startActivitySync` also adds CLEAR_TOP. Explicit runner arguments and exact launch flags must therefore be reviewed; the observer must not launch, recreate, close or finish an Activity. A no-restart flag alone does not suppress AndroidX cleanup. [Pinned monitor source archive](https://dl.google.com/dl/android/maven2/androidx/test/monitor/1.7.2/monitor-1.7.2-sources.jar).

**The actual callback may precede foreground recheck.** Registry delivery at ON_START can occur inside `super.onStart`, before the setup override's foreground call. The initial phase can therefore be CHECKING rather than MISSING. The old-result proof should require non-PICKING synchronous rejection, unchanged phase and zero source opens, then separately observe MISSING. The added primitive observer runs after the unchanged production handler and receives no URI/source. It observes synchronous admission, not asynchronous import completion; valid publication/READY needs separate evidence.

The coordinator identified a further admission prerequisite: the normal setup bootstrap calls the actual candidate store's `installed()` path, which could hash real weights if its fixed root unexpectedly existed. Exact read-only existence and symlink absence checks for `no_backup/local-model-v1` must precede bootstrap and pass again at final closure; an unexpected root aborts without reading its contents or resetting it. The driver may use only the setup chooser and must never start inference or navigate to the engine shell.

**UI automation has one owner.** Android15's accessibility manager rejects a second registered automation service and removes it on owner/client death. Instrumentation finish reports completion before posting connection shutdown, so a terminal result is not a synchronous service-release oracle. The independent driver and final observer must be serialized, with no overlap or blind retry after uncertain cleanup. [Android15 automation manager](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/android-15.0.0_r1/services/accessibility/java/com/android/server/accessibility/UiAutomationManager.java).

**Built-in dumps have success and cleanup traps.** `DumpCommand` connects and configures hierarchy compression before entering its cleanup `try/finally`. It then waits for one second idle, with a ten-second global idle timeout. Null-root or idle-timeout paths can return without XML; the underlying dumper catches write errors, so a footer alone also cannot establish success. Require bounded valid XML, the exact success footer, and known client termination; connection/setup failure remains uncertain ownership. [Android15 dump command](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/android-15.0.0_r1/cmds/uiautomator/cmds/uiautomator/src/com/android/commands/uiautomator/DumpCommand.java), [descriptor/thread wrapper](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/android-15.0.0_r1/cmds/uiautomator/library/testrunner-src/com/android/uiautomator/core/UiAutomationShellWrapper.java), [XML dumper](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/android-15.0.0_r1/cmds/uiautomator/library/core-src/com/android/uiautomator/core/AccessibilityNodeInfoDumper.java).

The initial `/dev/tty` idea has a transport prerequisite: a piped host runner has no local terminal, and `adb shell -t` allocates a remote terminal only when local stdin is a terminal; `-tt` forces allocation. A fixed fresh shell-only directory and unique XML filenames can avoid that assumption. Such a variant needs explicit namespace admission, owner/mode/path checks, no clobber, finite file/count/byte limits and retained local diagnostics only. It must not delete old temporary data. [Official adb command-line source](https://android.googlesource.com/platform/packages/modules/adb/+/android-15.0.0_r1/client/commandline.cpp).

**A tap reports input injection, not application success.** The built-in input command injects down/up coordinates; it does not authenticate the foreground package or prove which control received them. The host must derive bounded coordinates from a fresh unique eligible node, independently confirm the expected foreground package, and observe the resulting callback/state. Wrong package, duplicate node, invalid bounds, changed foreground and stale dump must fail closed. [Android15 input command](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/android-15.0.0_r1/services/core/java/com/android/server/input/InputShellCommand.java).
