## Lifecycle and authority requirements before execution

Pinned [Engine.kt](https://github.com/google-ai-edge/LiteRT-LM/blob/bda624851d74be34d4e1f7fac1fc4155939539c7/kotlin/java/com/google/ai/edge/litertlm/Engine.kt) permits distinct Conversations under one initialized Engine. Engine initialization, generation and native close belong off Main. Both Engine.close and Conversation.close reject repeated close; explicit owner state must track successful returns. Cancellation is delivered through onError(CancellationException), not necessarily onDone, and the SDK does not promise rollback. Cancelled/uncertain turns must abandon their Engine rather than reuse a cancelled Conversation's state. The existing callback-visibility limits still apply: SDK-visible Message channels/content are not a lossless guarantee about hidden native content.

A Java terminal latch alone does not prove native callback teardown. Successful Conversation close, Engine close and joined blocking native preparation must precede commit. A blocked initialize/cancel/close or undrained callback is ownership uncertainty, not graceful disposal. Separate native-prepare and SDK-runner execution contexts are essential: the blocking Rust preparation waits for provider responses, so running its request pump on that same occupied worker would deadlock. The provider itself must remain nonblocking and retain no Java references. Ticket scope, immutable request/schema/budget, consume-once responses, cancellation/drop/close invalidation, bounded repair and original durable request identity require adversarial tests before model execution.
