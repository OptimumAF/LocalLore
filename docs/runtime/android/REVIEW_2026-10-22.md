# Independent Android experiment boundary review

Scope: M01.02 Android experiment and supporting M01.03/M01.05 preparation.
The reviewer used a separate branch/worktree with exclusive ownership of this
review, source-review evidence and `benchmarks/test_android_runtime_ownership_review.py`.
The coordinator owns production experiment changes, integration and emulator
execution. No reviewer ran ADB, a model, the Android SDK or a physical phone.
Reading an already downloaded AAR and running synthetic host tests are described
separately below.

## Process ownership decision

Killing the host ADB subprocess cannot establish remote native termination.
The initial host-side PID/start-time verification design also left a gap between
the last identity check and sending a signal. The coordinator replaced it with
a small Android supervisor that owns one direct child. It keeps the child's PID
unreaped until cancellation/deadline processing finishes, then records completion
after waitpid. It never signals after reaping. Host cancellation writes a marker
in an exact UUID directory; host code does not kill a supplied PID or process name.

Source review checked the release barrier, monotonic deadlines, fixed argv
execution, nonblocking/no-follow regular request-file check, EINTR handling,
TERM/KILL escalation, explicit failure when reaping cannot be established and
atomic owner/done files. The supervisor handles TERM/INT/HUP by requesting child
cancellation rather than immediately orphaning the child. The native helper's
independent 90-second alarm is another abrupt-process bound, distinct from
cooperative SDK cancellation. Descendant ownership is deliberately limited to the
reviewed helper/oracle paths that do not spawn children. It is not a general
untrusted-process sandbox.

Remote cleanup requires both the supervisor's completion record and disappearance
of its original process identity. A completed host ADB job alone is insufficient.
Unproved remote cleanup leaves the UUID directory in place. Known files are
removed explicitly only after verified process cleanup; no recursive removal or
kill-by-name is used. A disconnected device, uninterruptible kernel task or
unavailable /proc observation must remain unknown/failed, never a successful
cleanup claim.

## Concrete findings and corrections

1. The first experiment accepted worker text when the remote/ADB cleanup flags
   were false or the worker return code was 23. Independently reproduced all
   three as incorrectly reported committed outcomes. The coordinator now gates
   text acceptance on successful process status, zero exit and both cleanup flags.
2. A role-launch exception escaped to the outer setup handler, losing the already
   attempted role. Independently reproduced the escaping exception. The coordinator
   now retains the attempted role and returns a fixed failure category.
3. Removing an owned run directory could throw from the worker's finally block
   and erase the verified process result. Independently reproduced this failure.
   Directory cleanup now has its own flag; removal failure cannot overwrite
   process ownership evidence or the attempted denominator.
4. An oracle preflight error array/object raised TypeError; unknown strings and
   booleans fell through to model launch. Independently reproduced all four cases.
   The coordinator now requires null or a known string error category before any
   model call. Deep oracle JSON raised RecursionError and duplicate keys were
   silently accepted. Strict controlled parsing now rejects both.
5. The SDK quiet-descriptor constructor initially leaked saved descriptors or left
   redirected output on partial construction failure. The runtime agent added
   staged rollback and independently attempts restoration/close of both saved
   descriptors. This was source-reviewed; injected Android descriptor failures
   were not run by this reviewer.

The coordinator additionally validates aggregate engine counters and exact
boolean fields, rejects unsupported thinking/template evidence and catches raw
ADB thread exceptions without printing private error text. The independent suite
checks these paths with synthetic canaries. The narrator receives only the
engine-approved narrator request; director-only context and generated text do not
enter the public aggregate report.

## Remaining validation and limits

The coordinator must execute supervisor cancellation, ignored TERM/KILL escalation,
deadline, blocked output, pre-release cancellation and ADB-client-death checks on
the selected emulators, then observe actual process reaping/absence. Actual
runtime model loading, missing/corrupt inputs, final-channel output, cancellation,
fresh owners, Rust validation/commit and final integrated checks remain separate
execution evidence. ARM64 cross-build success is not ARM64 execution. No phone,
model-quality, sustained-memory/thermal, durable-save or production backend gate
is accepted by this review.

Pinned SDK source says cancelled sessions are unsupported for reuse. Native close
waits for session work but ignores a wait error; entering a Java terminal callback
does not prove all JNI callback cleanup has finished. A successful close return,
balanced measured owners and separately verified package termination are finite
observations, not a universal native leak guarantee. Abrupt watchdog/force-stop
cleanup must be reported separately from cooperative cancellation. See the
[source follow-up](SOURCE_REVIEW_2026-10-22.md) for exact official references.
