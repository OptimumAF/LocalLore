# Bounded warm-role exchange v1

Development experiment for M01.02/M01.04/M01.05, stacked on #40. This is not a
gameplay API or a production backend decision. Existing worker request/result v1,
SDK0.18.1, model hash, context4096/CPU4 and role output caps remain unchanged.

The host proves the exact installed APK identity, drains/stops previous
instrumentation, creates a fresh private `files/warm-<session>` directory with
create-only semantics and marker `owner-v1` containing `locallore-warm-v1`.
`session` is exactly 32 lowercase hexadecimal characters generated by the host,
never model output. Instrumentation mode `warm` receives only that validated
session token. Java rejects a nonmatching/symlinked directory or marker. No
arbitrary path, SQL or model tool is accepted. Session IDs never enter public
reports or model prompts.

Fixed files inside that directory:

| File | Publisher / reader |
| --- | --- |
| `request-1.json`, `request-2.json` | Host / SDK; exact worker request v1, at most32768 UTF-8 bytes |
| `result-1.json`, `result-2.json` | SDK / host; strict exchange envelope, at most131072 UTF-8 bytes |
| `cancel` | Host / SDK; empty file requesting cooperative abandonment |
| `owner-v1` | Host / SDK; fixed experiment ownership marker |

Each JSON publisher writes `<filename>.partial`, closes it, and atomically
renames it to the final name. A final name is never replaced/reused. Readers
observe only final files and refuse oversized/invalid UTF-8, duplicate JSON keys,
unknown fields or wrong version/step/session. `request-1` must be director and
`request-2` narrator. SDK consumes each once, in order. The host publishes step2
only after the existing actual Rust oracle validates step1. A repeated step,
wrong role or an out-of-order final file is rejected, never treated as progress.

Exact result envelope:

```json
{"version":1,"session":"00000000000000000000000000000000","step":1,"result":{"version":1,"status":"completed","text":"Untrusted synthetic result","error":null,"load_ms":1,"generation_ms":1,"input_tokens":10,"output_tokens":3,"schema_enforced":true,"thinking_disabled":true,"template_applied":true}}
```

`result` is the existing worker JSON object, including untrusted text; no new
fields are added to it. The displayed token is synthetic; real tokens are unique.
Step2 uses integer2. Text remains
private transient IPC and goes only to Rust validation. Public reports contain
bounded role/error/timing/ownership metadata. Final instrumentation uses the
existing `result_base64`/`metrics` envelope, with an empty successful worker
result on two-role completion or a fixed worker error on abandonment. It must
not republish either role's generated text.

The SDK initializes exactly one Engine, creates/closes a fresh Conversation per
role, and closes the Engine after step2 or abandonment. No prompt/KV conversation
is shared between roles. `load_ms` is the Engine initialization time on step1,
zero on step2. Metrics retain the existing owner counters plus `warm_roles`
(completed role count,0..2), `warm_engine_reused` (true only after step2), and
`warm_cancel_observed` (true when the session cancel marker was observed).
Existing worker-off-Main, heartbeat and callback/owner flags remain applicable.

The SDK polls cancellation while waiting for the next request and while an async
generation is active. Active cancellation calls `cancelProcess`, waits for its
terminal callback, discards cancelled output, then closes Conversation/Engine;
cancelled owners are never reused. If a callback cannot drain, the independent
process watchdog/controller owns abrupt termination; no graceful close is
claimed. The existing90-second independent watchdog remains. Host overall turn
budget is60seconds, including warm handshake/role/oracle work after provisioning;
cleanup has a separate bounded allowance. Timeouts never auto-publish step2.

The host joins/cancels its sole instrumentation launcher before the final
hash-verified package stop/absence check. Only then may it remove the listed
known files, their `.partial` files and this exact owned directory (nonrecursive
`rmdir`). Unknown launcher/process cleanup retains files and prevents commit.
Rust narration/commit runs only after two valid roles and verified final owner,
launcher/process and file cleanup. No prepared or cancelled draft becomes canon.
Fresh-session recovery creates a new token/Engine rather than reusing a cancelled
Conversation. A host crash leaves no accepted turn; later package stop and
explicitly owned cleanup are distinct from proof of cooperative disposal.
