## Implemented ownership and protocol

[Warm protocol v1](WARM_PROTOCOL.md) freezes the coordinator/SDK boundary.
WarmExchange accepts only an exact lowercase session token, canonical private
session directory, regular non-symlink marker and fixed filenames. It bounds
reads, retains original consumed request/result bytes, invokes the existing
duplicate-key/UTF8/type-strict Request parser and checks director/narrator order.
Unknown entries, oversized files, changed consumed bytes, early foreign results
and narrator requests before director result publication fail closed. Empty
`cancel.partial` is allowed while the host atomically publishes `cancel`; only
the final marker requests cancellation.

Each private result is an exact version/session/step/result JSON envelope,
published through a create-only partial and atomic rename after existing-final
rejection. This is a single SDK publisher experiment with an explicitly owned
host. Java atomic rename does not itself guarantee no replacement against a
hostile same-UID peer racing final-file creation; that actor is outside this
benchmark's ownership assumption. Existing-file/repeated publications are
rejected and tested. No arbitrary path or prompt is synthesized in Java.

WarmRunner initializes once, creates and closes a fresh Conversation per supplied
role and closes the Engine after both roles or abandonment. Step1 reports actual
initialization milliseconds; step2 reports zero load. The host must validate the
director through Rust before publishing the narrator request, and owns all final
validation/commit decisions. JVM tests alone cannot prove that host behavior.

Cancellation is polled during request waits and active async generation, also
after terminal callbacks and owner close before publication. Active cancellation
calls cancelProcess, waits up to five seconds for the terminal callback and drops
output. Uncertain callback or owner-close completion prohibits deleting its
parent Engine and causes process termination without a successful final bundle.
The existing independent90-second watchdog remains; initialization, cancel or
native close can themselves block. The host retains its overall60-second budget
and separately bounded cleanup. A timeout/watchdog kill is never graceful-disposal
evidence. Final instrumentation success contains empty text only; role text stays
in private exchange files. Counters/booleans distinguish reuse, completed roles,
observed cancel marker and cancelled terminal drain. All existing modes remain.

## Verification scope

Run with the existing Java17 Gradle daemon and Android SDK selected:

```powershell
python benchmarks/spike/android/litert/build.py --java21 'C:/Program Files/Java/jdk-21' --offline --clean
python -m unittest discover -s benchmarks/spike/android/litert -p 'test_*.py' -v
git diff --check
```

The final source build/audit identities and exact counts are recorded in
[machine evidence](WARM_SDK_VERIFICATION_2026-10-22.json). Model-free JVM tests
exercise real filesystem protocol checks and an injected lifecycle backend;
they load no native engine/model. One earlier build failed because the tests
used Files.readString/writeString absent from Android's compile bootclasspath;
the tests now use bounded/explicit UTF8 byte operations. Independent review also
found a marker-newline integration mismatch, early foreign result gap and
legitimate in-flight cancel.partial race; the corresponding sources and
regressions were corrected before final freeze.

This SDK agent performed no ADB, installation, emulator, phone, model transfer or
inference operation. Neither fake callbacks nor an APK build proves native
cancellation, role isolation or model quality. The coordinator must execute the
fresh APK on both selected emulators, retain every attempt and report verified
cleanup before using a result in the actual Rust oracle. No physical-phone,
ARM64 execution, sustained thermal/memory or production inference qualification
is inferred.
