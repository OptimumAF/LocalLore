# Independent M01 host-spike review

Review task: M01.02 host compatibility and supporting M01.03 synthetic role
boundary. Separate worktree `LocalLore-spike-review`, branch `review/m01-spike`,
baseline `3a7cb82`. The coordinator owns integration and task acceptance. This
report is finite source/test evidence, not human acceptance or a production
runtime/model decision.

## Scope

Reviewed the coordinator's Python subprocess harness and Rust synthetic oracle,
the LiteRT one-shot Python worker, and the llama.cpp Python worker and native
helper. The harness uses pinned local model hashes, fixed worker paths, a shared
inference deadline, combined bounded pipe capture, and a Windows job before
releasing worker stdin. Workers validate their bounded input before loading
native inference or spawning the native helper. Windows job ownership includes
the helper. There is no generic model tool executor or production app dependency
in this slice.

The Rust example obtains actual typed requests and observer-filtered context from
the engine. Its accepted preview supplies only an exact public description to a
separate narrator call. The engine's existing exact narration rule remains in
force; this is an exact-render compatibility test, not creative prose quality or
approval to invent consequential facts. The synthetic player's director context
can include the player's known secret; that context does not enter narrator
input. Invalid spent-item and unlearned-ability intents fail preflight before a
model call. Those cases test safe preflight, not the director model's ability to
reject an invalid player intention.

## Concrete findings and responses

1. The minimal upstream completion CLI does not propagate parsed reasoning
   settings through its chat-format helper. Independently confirmed from the
   pinned source; passing `--reasoning off` alone would have been insufficient.
   The runtime agent replaced this path with a small native helper using the
   actual embedded template through `common_chat_session`, explicit non-thinking
   inputs, disabled tools, and parsed final-content output. Template input parts
   are tokenized without special-token recognition for user text. No approximate
   hand-written chat template or terminal-marker stripping is needed.
2. The LiteRT quiet-output context skipped its Python flush on exceptional exit.
   Buffered private diagnostic text could escape after descriptor restoration.
   The runtime agent moved flush into the `finally` block while descriptors
   still point to the sink and added a subprocess regression. Independently ran
   the updated suite: that regression and all nine other tests passed.
3. The parent response parser raised exceptions for a lone surrogate, array or
   object error category, and deeply nested JSON. Independently reproduced all
   four failures. The coordinator added strict scalar validation and a complete
   controlled parsing boundary. Repeated all four probes: each now returns the
   invalid-response result, with no exception.
4. Cleanup originally closed buffered pipes after reader-join failure, which
   could wait on a reader's buffer lock. The coordinator switched to unbuffered
   pipes, handles partial stdin writes, and avoids synchronous close when cleanup
   did not complete. Cleanup failure remains explicit rather than being reported
   as successful release.
5. The initial deadline reset per role. The coordinator changed it to one
   remaining inference budget after local hash verification, shared by director
   and narrator. Cancellation offsets use that same start; an already-cancelled
   invocation returns before process creation. Hashing and oracle setup are not
   measurements of full-turn latency.
6. The Rust error fallback originally asserted canonical equality without
   measuring it. The coordinator changed fallback evidence to indicate that the
   ephemeral state is discarded. Successful preview equality and exact retry
   checks remain separately measured. A discarded ephemeral engine is not a
   crash-safe persisted transaction.

One integration detail was sent to the coordinator for reconciliation: both
workers must share a finite accepted error vocabulary. Valid native failure
categories must not be relabeled as malformed worker output merely because the
parent initially listed only LiteRT categories. Arbitrary error text must still
be rejected.

## Limits and remaining acceptance

The native helper and LiteRT worker currently use different generation settings
and different models. The results can establish independent compatibility smoke
behavior, not a controlled model-quality or speed ranking. Report their settings
and every attempted call, including rejection, timeout and cancellation. A
single exact-render fixture cannot establish language quality, distinct voices,
repair rate, warm reuse, sustained behavior, tokenizer parity, or complete-turn
latency. Separate cold workers do not demonstrate one loaded model reused across
roles.

Source review found no new concrete boundary blocker after the listed corrections,
subject to the error-vocabulary reconciliation and coordinator's final tests.
Actual runtime/model execution, corrupt-file behavior, real inference
cancellation, final integrated tests and public aggregate evidence remain the
coordinator/runtime agents' responsibility. No physical phone is available in
this review, no ARM64 execution was performed, and no M01 checklist is accepted
by this report.
