## Shared core disposition

The reviewed native-only `Host::inspection_snapshot` checks trusted Full-mode
permission, live session/scope and explicit expected head, then captures a
validated Engine from the shared Store's coherent transaction. The pure builder
runs after capture. It does not write files, copy a live database, hold a database
transaction during formatting, generate narration or mutate gameplay.

Diagnostics is the default and contains structural metadata/counts plus a
manifest, without story prose or the seed payload. It still contains opaque
story/branch IDs, revisions and a timestamp; it is not an anonymity guarantee.
Player and Full are explicitly private story exports. Player uses existing
character-context eligibility, owned inventory, outgoing relationships and
visible-source thread filtering. Full intentionally includes hidden knowledge
and other characters. Neither is a playable archive.

A source audit found that the first in-progress validator could relabel spoiler
files as diagnostic content or a playable archive. Before the first independent
execution, `26e209f` added mode/privacy/inventory/view/head consistency checks.
The corresponding adversarial tests pass. No remaining capture/privacy defect
was demonstrated by the eleven focused cases below.

**Structural validation is not authenticity.** Anyone editing exported files can
recompute checksums and relabel metadata; a consistent Full bundle can be made to
claim Player visibility without proving that claim. A test deliberately
demonstrates this limitation and verifies that the supported Player capture
still filters the canonical engine and that the Host exposes no import command.
Checksums identify reviewed bytes and detect accidental changes, rather than
granting canon, generation, observer or trusted-origin authority. The native
broker must retain the exact captured bundle behind its private preview token;
it must never accept a renderer/external replacement bundle on save.

## Native/export acceptance still requires separate evidence

user destination selection, same-bytes publication, staging/nonoverwrite/atomic
rename, cancellation/disk-full cleanup, symlink/junction traversal prevention,
Reveal/Open actions or the consistent database-copy action. Those boundaries
belong to the desktop adapter and its app-owned native harness. Their reviewed
source and exact executed evidence must be attached separately before D03's full
gate is accepted. Editing a derived inspection file must never change live canon.

revision/media type. Current limits are 32 MiB total bundle and eight files
including the separately written manifest (one diagnostics file or seven story
views). Summaries and retrieval indexes remain honestly unsupported. Current
events are player-request events; future background/NPC receipts must retain
observer eligibility before attaching transcript/provenance.
