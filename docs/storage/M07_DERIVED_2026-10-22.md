## Frozen integration design

The coordinator owns real Store/lib/migration/open/verify and core eligibility
integration. All module functions receiving a SQLite connection are crate-private
borrowed-owner helpers. No connection is opened here, and no SQL, file path,
accepted-event parser or raw connection becomes an app/model API.

```rust
prepare(&Engine, &PrepareRequest, &dyn Fn() -> bool) -> Result<PreparedMemory, MemoryError>
publish(&mut Connection, PreparedMemory, &dyn Fn() -> bool) -> Result<PublishOutcome, MemoryError>
read(&Connection, &Engine, &PrepareRequest, &dyn Fn() -> bool) -> Result<SummaryPacket, MemoryError>
search(&Connection, &Engine, &SearchRequest, &dyn Fn() -> bool) -> Result<Vec<SearchHit>, MemoryError>
invalidate(&mut Connection, &Scope, observer: &str, expected_revision: u64,
           &dyn Fn() -> bool) -> Result<(), MemoryError>
```

`PrepareRequest` fixes scope, current completed expected_revision, actual actor,
from_exclusive, through_revision=current head, and `SceneWindow` or exact typed
entity kind+ID. Entity kinds are actor/item/location/ability/fact/commitment.
Historical heads, branch forks, chapter detection, alias inference and sources
without an accepted observation are unsupported. A scene window is an explicitly
selected event segment, not a claim that automatic narrative scene detection exists.
A nonzero start boundary must be an observer-eligible completed event; probing
hidden and absent boundaries fails with the same fixed category.

`PreparedMemory` has private fields and no Deserialize. It carries an immutable
request, exact original accepted source envelopes and extractive packet. Only the
shared Engine's borrowed `visit_actor_observations` can supply its events. That
port must validate exact scope/current head/actor/range and use the existing
lineage+witness predicate, checking cancellation at bounded scan intervals.
There is no second witness filter and no whole CharacterContext/history clone.
A global-history cap was rejected because it would make an actor's result depend
on how many excluded events existed. Caps apply only to selected eligible events.

Extractives preserve typed accepted outcomes: `statement`, `belief`, and
`canonical_observation`. Only consecutive observed TimeAdvanced outcomes with
matching endpoints coalesce into an `observed_time_span`, retaining every source
sequence. An allegation remains an attributed statement. Private thought/original
player input, narrator text, omniscient state, unknown seed truth and prior
summaries are never summary inputs. This is a deterministic typed event digest,
**not an LLM archivist, semantic reflection or demonstrated narrative compression
quality**. Model and prompt provenance are explicitly null; fixed method and
format version, actual source revision/range/IDs, scope, actor and visibility are
stored. Source seed-only commitments/facts remain the exact compiler's authority,
not fabricated accepted-event summaries.

## Publication, freshness and migration proposal

`publish` takes an IMMEDIATE transaction, verifies exact root branch/head and
compares every selected original envelope with the owner's accepted_events rows.
It writes only the derived cache; cancellation or verification failure rolls back.
Same key/basis/packet is idempotently unchanged. Source acceptance is never based
on hashing or trusting the cache's own bytes. `read` reconstructs the packet from
the actual Engine and compares complete canonical serialized bytes. Changed cache
text, target, attribution, source list, duplicate JSON keys or envelope cannot
silently become accepted memory. The future Store wrapper must obtain this Engine
through validated replay on the same owner; helpers do not authenticate an
arbitrary external database or replace Store::resume.

`read`/`search` hold one bounded coherent main-database read snapshot. The packet
basis is not advertised as a newer head if a writer commits after that capture.
A changed head excludes stale rows; no stale packet is combined with current
state. New maintenance rebuilds from original accepted events. Publishing a fresh
basis removes older rows for that actor/scope partition. Explicit invalidation
deletes only that partition after expected-head validation. Reopening/retrying a
cache operation is supported; a durable job queue, partial job cursor, correction
workflow, exact-delta supplementation and branch inheritance are **not implemented**.
Cancellation is checked before work, per accepted event/SQL row and immediately
before transaction commit. A panicking private cancel callback is treated as
cancellation, so it does not unwind out of the Store helper or publish partial data.

`DERIVED_SCHEMA_SQL` proposes one ordinary STRICT `derived_memory` table with
story/branch/actor foreign keys, target/range key, source_revision, summary_version,
fixed method/visibility and bounded JSON. It executes **only on test-owned schema
fixtures**. Root must design/apply a backed-up v1→v2 migration, change the current
version-1-only migration record constraints, preserve historical schema fixtures,
exactly verify the new shape, and prove reopen/recovery/Android compatibility.
Nothing in this prototype relaxes existing schema-v1 verification or treats an
unrecognized database as owned. No persistent FTS shadow/dynamic tables are added.

## FTS privacy and bounds

The pinned bundled libsqlite3-sys build enables SQLITE_ENABLE_FTS5. Runtime tests
must still exercise the actual library, rather than infer availability from that
flag. The [official FTS5 documentation](https://www.sqlite.org/fts5.html) documents
FTS virtual tables and MATCH expressions; this module uses literal quoted tokens
and bound SQL values. Input cannot select SQL columns, boolean operators, prefixes,
NEAR grammar, tokenizers or an arbitrary SQL statement.

The owner first selects only exact story/branch/actor/current-revision cache rows.
It rederives/validates each against eligible original sources before materializing
the corpus. Only that verified partition enters one fixed TEMP FTS5 table on the
same borrowed owner connection. Search returns bounded packet hits in stable
partition order, never global BM25 scores/frequencies, snippets, unrelated row IDs,
other-observer counts or exclusion metadata. The temporary table is dropped on
success, cancellation and query error. No database connection, global search index,
external service, embedding model or competing ledger is introduced.

Limits: 256 selected eligible source events, 1 MiB total source envelope bytes,
64 KiB complete packet, 32 packets per actor/scope partition, 256 query bytes,
16 literal terms and 16 hits. Overflow stops safely. These are prototype safety
caps, not measured production throughput/latency or token counts. FTS may match
structural keys in the typed JSON digest; relevance/alias/paraphrase quality is not
claimed. Main source scans use the existing borrowed actor filter and cancellation;
excluded histories never consume a selected-event cap or produce exclusion counts.
